## 0. Главная задача

Исправить конкретные дефекты текущей реализации, подключить созданные данные к настоящему учебному потоку и выполнить оставшиеся P0/P1 предыдущего ТЗ.

**Нужен рабочий пользовательский результат:** человек открывает «Сегодня», вспоминает слово до показа/озвучивания ответа, получает корректную обратную связь, затем встречает это задание в назначенный срок. Не начинать с полной переписи проекта. Сохранить правильные эталоны, полезную Room-схему, работающие части интерфейса и аудиокэша. Доработать их так, чтобы требования выполнялись сквозным пользовательским сценарием, а не наличием класса, JSON-поля или кнопки.

### V4-A02. Кэш и публикация должны выдерживать ошибки

Input hash включает фактический нормализованный речевой текст, язык/голос, настройки синтеза, версию словаря произношения, нормализатора и профиля кодирования. Настройки обычного воспроизведения на телефоне не запускают новый синтез.

Переиспользование файла разрешено после сравнения input hash, контрольной суммы готового файла и проверки декодирования/длительности. Размер >500 байт не является проверкой корректности.

Генератор:

1. Строит план изменений без записи для dry-run.
2. Пишет результаты и новый манифест в staging.
3. После каждого успешно проверенного сегмента сохраняет возобновляемый кэш.
4. На ошибке обязательной роли завершает выпуск ненулевым кодом, перечисляет неготовое и оставляет прежний рабочий пакет.
5. Публикует пакет/манифест согласованно только после проверки полного графа.
6. Не удаляет прежний рабочий набор до успешной замены.
7. Возобновляет прерванную работу, не синтезируя заново корректные неизменённые сегменты.

Валидатор обязан возвращать ненулевой код при missing, hash mismatch, corrupt, неполном покрытии либо несоответствии сценария актуальному содержимому. Само успешное чтение JSON не является успехом проверки.

**Обязательные отрицательные тесты:** отсутствующий файл; удалённая привязка; невалидные MP3-байты нужного размера; изменённый перевод; изменённый словарь произношения; четыре отказа провайдера; прерывание после нескольких готовых ролей; совпадающий речевой текст у двух карточек.

### V4-A03. Знакомство должно озвучивать смысл, фразу и перевод

Основной голос во всех новых сегментах — Andrew. Не исправлять недостаток содержания заменой тембра.

Три сценария:

- **Знакомство:** EN-термин → разбор имени при наличии → понятное RU-объяснение → естественная EN-фраза → перевод фразы. Один цикл по умолчанию.
- **Слушать/повторять:** EN-термин → краткий понятный смысл → EN-фраза → RU-перевод по настройке; 1/2/3 полных цикла по явному выбору.
- **Проверка:** только допустимый стимул → время на ответ → раскрытие ответа после действия пользователя/конца явно выбранной аудиопроверки. До попытки нет озвучки русского ответа в EN → смысл и английского ответа в RU → EN.

Нельзя снова заменить смысловую озвучку только `meaning_ru_short`. У `zip` при знакомстве слышны объединение по позициям, имена/оценки и остановка на короткой последовательности.

У `rsplit` обязательно слышны:

- имя API в выбранной проверенной форме, например `R split`;
- right — «правый/справа», split — «разделять»;
- **right split — «разделить справа»**, приблизительно «райт сплит», как учебная расшифровка имени;
- при ограничении количества разделений выбираются правые разделители, а порядок частей сохраняется;
- EN-фраза и её русский перевод.

Не смешивать мнемоническую расшифровку right split с буквальным чтением идентификатора и не возвращать псевдо-IPA `/rsplit/`. EN/RU-фрагменты синтезируются раздельно, если это требуется для правильного произношения.

**Проверка:** один сценарий строится из той же версии контента, которая показана пользователю; его можно вывести текстом и сопоставить с манифестом. Для zip/rsplit это проверяется адресно и прослушиванием пилота.

### V4-A04. Один счётчик циклов, корректные кнопки и ошибки

В учебном пакете одна запись содержит один сегмент. Устаревший трек с двумя внутренними циклами нельзя повторять как одно слово или одну карточку.

- Из активной проверки убрать fallback на полный legacy EN/RU-файл. При отсутствии нужной роли явно показать недоступность звука/ошибку пакета. Выпускной контроль должен предотвращать такое состояние для ready-карточек.
- Если legacy-слушание временно сохраняется, назвать его отдельным режимом и не смешивать его циклы/прогресс с новой практикой.
- «Слово» воспроизводит только слово; «Фраза» — только EN-пример; кнопки не перелистывают и не ставят оценку.
- Полный цикл завершается после последнего сегмента выбранного сценария. При N=3 каждая входящая в него роль звучит ровно три раза.
- Изменение N применять со следующей карточки с понятным отображением.
- Pause/Resume сохраняет позицию сегмента, номер цикла и оставшуюся паузу; Replay начинается сначала.
- При смене карточки обновлять текущий ID даже на паузе. Play всегда продолжает видимую карточку/зафиксированную сессию по явному контексту.
- Отменять устаревшие completion/таймеры токеном сессии. На последней карточке диалог завершения появляется один раз.
- Ошибка чтения/декодирования переводит в Error, а не completion; повтор/пропуск явные и не считаются успешным учебным ответом.

**Тестовый player/clock:** N=1/2/3; пауза в середине звука/между ролями/в окне ответа; смена 20 карточек; Stop во время loading; повреждённая роль; последняя карточка; возврат из меню. Дополнительно подтвердить критические случаи на Android.

## 5. Починить миграцию и сохранность ответов

### V4-M01. Правильный перенос старых отметок

**Фактический старый формат:** preferences `english_flashcards_progress`; ключ `card_status_<id>`; значения `NEW`, `HARD`, `LEARNED`.

Читать именно его и явно поддерживаемые дополнительные варианты, если они реально найдены. Текущие `EnglishCardsPrefs`, `learned`, `in_progress` не являются заменой фактическому источнику.

Требования:

1. Упаковать карту `legacy_id_map.json` в доступный приложению пакет и использовать её при переносе.
2. HARD → ручная сложность/ранняя проверка. LEARNED → прежняя отметка знакомства, требующая проверки. NEW → новый элемент.
3. Не придумывать прошлые reps, lastReview, stability и правильные ответы. Не переносить знакомство с чтением сразу на продуктивный навык.
4. Обработать split старого ID 17 явно: языковая основа связана, разные API не получают общее состояние знания автоматически.
5. Старый ProgressManager не остаётся параллельным основным источником статистики после миграции.
6. Перенос состояния/пометок/версии миграции транзакционный и идемпотентный. Неизвестные ID сохраняются в отчёте, а не случайно привязываются к другой карточке.
7. При увеличении корпуса новые записи добавляются даже при уже установленном migration flag. Проверка «в таблице что-то есть» не заменяет применение версии контента.

**Отдельно исправить установки уже выпущенной текущей версии:** создать repair-migration. Сохранить реальные `review_events` и заметки. Не перезаписывать настоящие свежие ответы старыми preferences. Ошибочно посеянные/неподтверждённые состояния отметить и направить на проверку; не уничтожать всю БД. Нельзя восстановить реальную длительность прежних ответов из константы 2000 — пометить такие данные как estimated/unknown.

**Проверки:** старые NEW/HARD/LEARNED; неизвестный ID; два преемника ID 17; частично выполненный перенос; повторный старт; уже оценённые v3-карточки; добавление новой карточки после миграции; обновление APK поверх установки без удаления.

### V4-M02. Оценка должна записываться один раз и целиком

- Ввести уникальный `attempt_id`/UUID события с ограничением уникальности в БД.
- Состояние scheduler, review event и состояние текущей сессии сохранять в одной транзакции.
- До подтверждения записи UI блокирует повторную отправку; повтор одного attempt безопасен.
- Измерять длительность реальным монотонным таймером с остановкой на фоне; не записывать 2000 мс всем ответам.
- Хранить тип задания, самостоятельность, использованные подсказки, число прослушиваний, версию контента и scheduler.
- Кнопка «Отменить последнюю оценку» восстанавливает предыдущие состояние/очередь и исключает отменённую оценку из статистики, сохраняя факт отмены.
- Сохранять текущую попытку, выбранный навык, очередь и состояние раскрытия при пересоздании Activity и завершении процесса.
- Автозвук не запускается сам после перезагрузки или открытия приложения.

**Принято, когда:** два быстрых тапа, повторная доставка события и перезапуск процесса не удваивают ответ; искусственный сбой между операциями не оставляет состояние без события; undo полностью возвращает due и счётчики.

## 6. Подключить настоящий планировщик и due-очередь

### V4-S01. Проверяемая реализация FSRS

Ветка Hard сейчас игнорирует рассчитанный `rawDays`, не реагирует на retention для рассмотренного состояния и превышает maximumInterval. Исправить её не отдельной косметической заменой числа, а сравнением всех переходов с эталоном.

Выбрать одну версию FSRS и конкретный release/commit эталонной реализации. Сохранить источник, лицензию, конфигурацию коротких шагов и тестовые векторы. Ссылки для исследования: [FSRS-Kotlin](https://github.com/open-spaced-repetition/FSRS-Kotlin), [ts-fsrs](https://github.com/open-spaced-repetition/ts-fsrs). Текущую формулу не считать доказанно совместимой только из-за названия класса.

Покрыть `New/Learning/Review/Relearning × Again/Hard/Good/Easy`, немедленный ответ, overdue, смену retention, maximumInterval, низкую stability, большие интервалы и нулевую историю. Предпросмотр и итоговая запись используют одну функцию и одинаковое время.

Регрессионный вход из аудита: Review, stability=15, difficulty=5, scheduledDays=10, прошло 10 дней. При maximumInterval=10 ни одна долгосрочная ветка не назначает 12 дней. Для retention 0,80/0,90/0,97 сравнить результат с выбранным эталоном, а не утверждать правильность нынешних 12 дней.

Изменение версии scheduler сопровождается миграцией сохранённого состояния и возможностью воспроизвести расчёт по истории. Интерфейсный слой не содержит независимой формулы интервалов.

### V4-S02. Реальная сессия «Сегодня»

**Где исправлять:** `MainActivity.kt`, session layer, DAO/репозитории, главный экран.

Кнопка «Сегодня» получает задания из расписания, а не `getCardsByCategory(...)` целиком. Порядок: наступившие короткие шаги → overdue → остальные due → новые в пределах лимита.

- Новые единицы: по умолчанию 10/день, настройка включает 0. Считать новые слова/значения, а не все производные задания отдельно.
- Сессии 5/10/20 минут. Истечение лимита не закрывает невыполненные due.
- Again возвращает карточку в реальный срок; если шаг ещё не наступил, доступны другие задания. При отсутствии других задач показать ближайшее время и возможность завершить.
- Не показывать сразу все направления одного слова подряд; фиксировать отложенные сходные задания, не считая их выполненными.
- Существующие категории становятся фильтром для сессии; отключение темы не обнуляет историю и due.
- Навыки имеют отдельные practice state. Запись всегда `.en_to_ru` вместо фактического выбранного задания недопустима.
- Применить внедряемый Clock. События UTC, учебный день в локальном поясе, граница по умолчанию 04:00. Проверить смену даты/пояса/системных часов.
- Во время активной проверки Next/Swipe не считаются правильным ответом; пропуск сохраняется без оценки.
- Свободное листание/слушание остаётся отдельным режимом и не меняет SRS без явной учебной попытки.

**Принято, когда:** карточка с due через неделю не включается как due сегодня; Again возвращается после предусмотренного шага; при лимите 0 новые не попадают в занятие; после перезапуска воспроизводится очередь и не теряются уже данные оценки.

## 7. Активное вспоминание и недостающие упражнения

### V4-L01. До ответа нет скрытой аудиоподсказки

В EN → смысл лицевой стимул — EN. Текст RU, его озвучка, name breakdown и код скрыты. В RU → EN скрыты английский ответ, его произношение и фраза, содержащая ответ.

Не включать полный `playCard` при открытии активной колоды. В этом режиме допустимо автопроизношение только самого разрешённого стимула. Тап по телу закрытой карточки не запускает переводной трек.

Знакомство, активная проверка и пассивное слушание явно различаются. Reveal после самостоятельной мысленной попытки допустим; отдельная подсказка, раскрывающая часть ответа, отмечается assisted. Для запланированной проверки после такой помощи итог Again, Good/Hard/Easy недоступны. В свободной тренировке — событие без роста интервала.

`revealedCardIds` не используется как вечное разрешение показывать ответ на слово: новый attempt начинает с закрытой стороны. Возврат внутри той же попытки восстанавливается осознанно, новая сессия не наследует открытые ответы.

**Проверка:** записать последовательность событий плеера до reveal для обеих сторон; в ней нет запрещённой роли. Проверить также TalkBack, notification title и доступность скрытых элементов.

### V4-L02. RU → EN, диктант, аудирование и cloze должны иметь экраны

Не ограничиваться `enabled_templates` в JSON. Для каждого режима нужны доступный вход, инструкция, стимул, ответ/раскрытие, оценка, запись события и возвращение к сессии.

- **RU → EN:** русский смысл с однозначным контекстом, ввод или мысленный/устный ответ с самооценкой. Английское слово не присутствует в prompt.
- **Диктант:** EN-звук без написания, поле ввода, проверка и подсветка различий. Разрешённые варианты задаются в данных.
- **Аудирование:** слово/фраза без субтитров до ответа, выбор смысла либо самостоятельная оценка после попытки; затем текст и перевод.
- **Cloze:** реальное предложение с корректным пропуском по токену/диапазону, достаточный контекст и набор допустимых ответов.

Нормализация ввода: Unicode, крайние пробелы, варианты апострофа, обычный регистр для слов. Для API регистр/скобки нормализуются только явно разрешённым правилом. Не игнорировать отрицания, окончания и предлоги. `authentication` и `authorization` не становятся одним ответом по похожему написанию.

Неверный результат не получает Good/Easy, даже если после показа эталона пользователь переписал ответ. Исправление случайной опечатки — отдельное видимое действие с записью в событии.

Количество подсказок и повторных прослушиваний хранится отдельно. Повтор самого стимула допустим и не равен раскрытию текста. Количество новых направлений не должно создавать бесконечный поток дубликатов на одно слово.

**Принято, когда:** каждое из четырёх направлений можно пройти от главного экрана до сохранённого результата; неправильный ввод проверяется; обновляется именно соответствующий `practice_id`; после перезапуска результат остаётся.

### V4-L03. Микроуроки и второй контекст

Упаковать 12 lesson-файлов в APK/проверенный пакет и реализовать список/плеер микроурока: правило → два примера → минимум три задания → обратная связь → итог. Сохранять прохождение независимо от знания отдельного слова.

Не маркировать урок выполненным по факту чтения JSON. Проверить правильные и неверные варианты, объяснения ошибок и повтор урока.

Не меньше 50 единиц получают второй отличный контекст. Использовать его в отдельной тренировке переноса/поздних повторениях, не меняя `practice_id` только из-за смены примера. Два поля `secondaryExampleEn/Ru`, которые никто не показывает, требование не закрывают.

**Принято, когда:** после чистой офлайн-установки доступны все 12 уроков, задания оцениваются и результат сохраняется; 50 вторых контекстов перечислены в отчёте и достижимы из приложения.

## 8. Статистика, поиск, настройки и резервная копия

### V4-U01. Честный главный экран и статистика

Главная кнопка — «Сегодня / Продолжить». Показать реальные due, новые единицы, оставшееся время и точку сессии. Из главного экрана доступны «Слушать», «Словарь», «Уроки», «Статистика», «Настройки».

Статистика основывается на сохранённых событиях и состоянии навыков:

- отдельные показатели для распознавания, вспоминания, написания и аудирования;
- самостоятельные успехи, ошибки, assisted и тренировки после раскрытия;
- активное время и время слушания отдельно;
- число слов и число заданий отдельно;
- due/overdue и фактический размер долга.

Первый Good/Easy не означает «слово выучено». Метку устойчивого вспоминания считать по отложенным самостоятельным успехам и интервалу по правилам V3. Прежнюю LEARNED показывать как историческую отметку, не как доказанное владение всеми навыками.

Убрать фиксированную заставку «синхронизация» и числа 1680/1529, не связанные с загрузкой. Загрузка показывает реальную операцию; экран занятия не открывается до окончания обязательной миграции/загрузки.

**Проверка:** 20 минут пассивного слушания не создают успешные review; один ответ не превращается в четыре выученных слова; отмена оценки пересчитывает показатели; длительности не равны постоянным 2000 мс.

### V4-U02. Словарь и настройки

Поиск по слову, русскому смыслу, фразе, API и алиасам. `rsplit`, `right split`, «разделить справа» находят нужный смысл. Два `filter` различимы по контексту. Тематика и namespace не подменяются первым случайным словом тега.

Фильтры: тема, навык, due/новые/сложные, избранное, приостановленные. Избранное и пользовательская сложность сохраняются независимо от SRS.

Настройки: дневной лимит, длительность, скорость, паузы, профиль/циклы аудио, перевод в слушании, IPA/русская подсказка, тема, размер текста, локальные напоминания. После перезапуска выбор сохраняется. Сброс настроек и удаление прогресса разделены.

### V4-U03. Экспорт/импорт и восстановление

Реализовать локальный версионированный JSON/ZIP через системный выбор файла. Экспорт содержит состояния, UUID событий, заметки, личные подборки, настройки, версии схемы/контента и checksum. Встроенное аудио повторно экспортировать не требуется.

Импорт: валидация → предварительный отчёт → транзакционное объединение/явная замена → итог. Повторный импорт того же файла не удваивает историю. Неизвестные ID и несовместимые версии отражаются явно; повреждённый файл не портит текущую БД.

Для конфликтов состояний использовать полную совместимую историю либо документированное правило; не терять события из-за одного сравнения lastReview. Перед полной заменой предложить сохранить текущую копию.

**Принято, когда:** экспорт → чистая установка → импорт восстанавливает due, события, заметки и настройки; повторный импорт ничего не удваивает; искусственно повреждённая копия отклоняется без изменения БД.

## 9. Фоновое слушание и доступность

### V4-P01. Медиасессия вместо удержания Activity

В «Слушать» добавить сервис/медиасессию с Play/Pause/Next/Previous в уведомлении и на заблокированном экране, audio focus и обработкой отключения гарнитуры. Активная проверка при уходе с экрана ставится на паузу; слушание продолжает только в явно включённом режиме.

### V4-P02. Проверить интерфейс на реальных ограничениях

Проверить TalkBack, 200% системного шрифта, узкий экран, длинные слова/переводы, клавиатуру и пересоздание экрана. Кнопки не перекрыты, ответы до reveal недоступны, фокус после reveal/проверки предсказуем.

Сохранить тёмную тему, добавить светлую и системную. Статусы различаются текстом/значком. Управление доступно без знания эмодзи и цвета, области нажатия не менее 48 dp.

Простая запись своего произношения остаётся локальной опцией P1 с разрешением только по действию пользователя, воспроизведением и удалением. Автоматическая оценка произношения — P2, не повод выдавать фиктивный балл в этой версии.

## 10. Ввести выпускные барьеры, которые действительно падают

### V4-Q01. Негативные пробы обязательны

Существующие 13 Python-тестов и 4 unit-теста FSRS сохранить, но расширить. Они проходят и при текущих серьёзных дефектах, поэтому сами по себе недостаточны.

Минимальный комплект регрессий:

1. **Неверная/пустая английская фраза или новый массовый шаблон** → ошибка контентной проверки/QA, а не безусловный ready.
2. **Правка исходника → build → check** → правка сохраняется, check не меняет файлы.
3. **Переименование/перестановка** → прежний ID и история сохраняются.
4. **Код из карточки с top-level await/неопределённым объектом, помеченный standalone** → проверка не принимает его как выполненный пример.
5. **Нет одного обязательного файла либо самой строки манифеста** → release audio validation exit != 0.
6. **Файл достаточно большой, но повреждён или checksum не совпадает** → не переиспользуется как готовый кэш.
7. **Ошибка всех ролей у одной карточки** → генератор exit != 0, прежний пакет сохраняется.
8. **Одинаковый сегмент у двух карточек** → обе получают правильные привязки.
9. **Выбранные 1/2/3 цикла** → ровно столько завершённых сценариев; legacy-повторы не умножаются.
10. **Скрытая сторона** → ни UI, ни аудио, ни accessibility не раскрывают ответ.
11. **due в будущем / due сейчас / Again / новые=0** → корректная реальная очередь и повтор по Clock.
12. **Оценка Hard и maximumInterval=10** → соблюдён предел и эталон выбранного scheduler.
13. **Старые preferences с uppercase-статусами** → правильная миграция без придуманных review.
14. **Двойной тап/сбой записи/undo** → атомарное одиночное событие и восстановимое состояние.
15. **Экспорт/импорт дважды/поломанный файл** → сохранность и идемпотентность.
16. **Урок в репозитории, но не в APK** → упаковочная проверка падает.
17. **Новая единица без аудио или упражнения** → не проходит как готовая офлайн-единица.

Тестовые фикстуры должны быть независимы от конкретного случайного порядка всей базы. Не фиксировать `len(cards)>=1680` как доказательство качества; проверять реестр требуемого покрытия и редакторских решений.

Для содержательной проверки не подменять утверждение «пример исполняется» поиском слов `Animal`, `scores` или строки ожидаемого результата. Должен исполняться текущий код из текущей поставки.

### V4-Q02. Проверить APK и путь обновления

Перед выпуском:

- Python tests, схема/редакторские статусы, примеры, аудиоманифест и упаковочное покрытие.
- Gradle unit tests, lint и сборка; instrumented/UI-проверки в доступной Android-среде.
- Сравнение текущих content/manifest с файлами внутри APK.
- Установка поверх прежней версии с образцом реального прогресса и проверка миграции.
- Чистая установка в авиарежиме: все обязательные режимы и аудио доступны.
- Фактические замеры запуска, поиска, начала локального звука и размера пакета с указанием устройства.

Версия из README, Gradle и метаданных APK согласована. Номер версии ТЗ V4 не обязывает называть приложение 4.0, но следующая поставка должна иметь versionCode строго больше уже выпущенного 2. Проверить подпись и не перезаписывать ключи. Debug/release обозначаются честно; отсутствие release-ключа описывается как ограничение совместимого обновления.
