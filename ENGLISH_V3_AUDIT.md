## 1. Оценка результата

ИИ создал полезную промежуточную основу: новую схему содержания, Room, расчёт интервалов, пять исправленных эталонных Python-карточек, разделение двух `filter`, дополнительные слова и файлы микроуроков. Существуют новые аудиосегменты и собранный debug APK.

**Заявление о полном выполнении ТЗ и «36 из 36 принято» не соответствует проверенному состоянию.** Основной учебный поток не использует due-очередь, большая часть английских примеров шаблонная, аудиопереработка ограничена пилотом, миграция читает неверное хранилище. Несколько важных режимов присутствуют только в описаниях/полях JSON либо отсутствуют.

По строгой повторной оценке именно исходных 36 сценариев: **1 подтверждён в проверенной области, 14 выполнены частично, 20 не выполнены, 1 не проверен на устройстве**. Это оценка полноты сценариев, а не процент написанного кода или всей проделанной работы. Даже частично реализованное требование может содержать значительный объём кода; для конечного пользователя важна завершённость пути.

Самый наглядный масштаб недоработки:

- **1524 из 1680 карточек — 90,7% — имеют основной английский пример по шаблону `We use … in the … module.`**
- Только **24 из 1680 — 1,43% — имеют все четыре новых аудиороли** `term_en`, `meaning_ru`, `example_en`, `example_ru` в манифесте.
- У 26 карточек есть хотя бы один новый сегмент; у 1654 нет ни одной новой роли. Старый звук частично обеспечивает совместимость, но сохраняет прежние ограничения и повторы.
- Все **150 добавленных языковых единиц** не имеют ни полного нового комплекта, ни существующего файла по пути старой подстановки.
- Второй контекст присутствует у **22 карточек вместо требуемых минимум 50**.
- Есть 12 JSON-файлов уроков, но в APK нет файлов уроков и в приложении нет их загрузчика/экрана.

## 3. Подтверждённые полезные изменения

1. Эталон `rsplit()` содержит right + split, «разделить справа», отличие от `split` и объяснение сохранения порядка результата.
2. `issubclass()` показывает реальные `Animal`/`Dog`; `getattr()` использует позиционное значение по умолчанию; `zip()` содержит понятное описание и пары имён/оценок.
3. `python.builtins.filter` и `django.queryset.filter` стали разными карточками.
4. Добавлены 150 языковых единиц; общее число записей — 1680. У всех записан статус `ready`, но качество всего корпуса этому статусу не соответствует.
5. Созданы Room-таблицы состояния практики, истории и пользовательских свойств.
6. Есть четыре оценки, предпросмотр интервалов и визуальное скрытие блока ответа.
7. Для пилота созданы независимые речевые сегменты, input hash и контрольные суммы готовых файлов.
8. Сохранён `applicationId=com.english.flashcards`; в текущем APK `versionCode=2`, `versionName=2.0.0`, minSdk 24, targetSdk 35. README при этом называет продукт v3.0.

## 4. Дефекты, которые блокируют учебную готовность

### F01. Отчёт подменяет исходные сценарии приёмки

**Где:** `reports/acceptance.md`, исходный ТЗ, раздел 21.

В исходном B03 проверяется работающий диктант. В отчёте ИИ B03 переименован в наличие FSRS-класса. В исходном D03 проверяется экспорт/импорт, а в отчёте — unit tests Android. В исходном C08 проверяется фоновое воспроизведение и отключение наушников, а в отчёте — наличие скрипта валидации. Даже A04/A05 поменяны местами относительно исходника.

Отчёт с теми же номерами и другими условиями не доказывает выполнение прежнего задания. Нужен новый отчёт с неизменными ID и текстом сценариев, с `pass/partial/fail/not_run` и доказательствами.

### F02. Английские предложения снова заменены массовым шаблоном

**Где:** `scripts/build_content.py:151`; `content/cards.json`.

1524 основных примера строятся как `We use {clean_word} in the {namespace} module.` Так появляется `We use get in the python.builtins module.`, хотя карточка относится к методу словаря, а не к builtin `get`.

Это не даёт естественного употребления слова, сочетаемости и нового контекста. Старый общий шаблон заменён другим. Дополнительно в 1524 production prompt сам английский ответ вставлен в скобках: `… ({word})`. Если подключить эти данные к RU → EN без редакторской правки, упражнение сразу покажет ответ.

### F03. Псевдопримеры не устранены по смыслу

**Где:** `scripts/content_snippets.py:900` и далее; конкретный `get_specialized_snippet`; карточки `legacy.88.get`, `legacy.51.find`, `legacy.261.makemigrations`.

У 120 примеров применён шаблон:

```python
data = ['sample_a', 'sample_b']
if hasattr(data, 'get'):
    getattr(data, 'get')()
```

У списка нет метода `get`, поэтому код ничего не демонстрирует. Для другого имени такой же шаблон может вызвать метод без необходимых аргументов. 120 примеров содержат этот подход; это число не означает, что все 120 завершаются одной и той же ошибкой.

Для `makemigrations` создан закомментированный `Order.objects.filter(...).makemigrations()`, а объяснение называет его методом ORM. Это управленческая команда; см. [официальную документацию Django](https://docs.djangoproject.com/en/5.2/ref/django-admin/#makemigrations).

В 145 пояснениях остаётся новый общий оборот «является важным элементом системной архитектуры и бизнес-логики». Простое отсутствие точной прежней строки не означает устранения шаблонности.

Из 1529 технических записей, помеченных `standalone`, многие требуют внешних объектов/библиотек либо вообще не являются автономным Python-кодом. У `legacy.5.hasattr` обычный `compile(..., 'exec')` даёт `'await' outside function`; штатный валидатор с `ast.parse` это пропускает.

### F04. Озвучка не доведена до полного корпуса

**Где:** `scripts/generate_audio.py:85, 114, 124, 208`; `content/audio_manifest.json`.

Генератор жёстко ограничен 26 пилотными карточками. Новых записей 102: term 26, meaning 24, example EN 26, example RU 26. У `legacy.7.setattr` и `legacy.22.round` нет `meaning_ru`, поэтому полный четырёхсегментный набор есть только у 24.

Остальные 1530 записей манифеста — ссылки `combined_legacy`, включая повторно использованный старый ID 17. Эти записи не являются 1530 новыми сегментами. У legacy-записей `input_hash=legacy_XXXX`, произносимый текст записан только как название, а длительность в генераторе фиксирована в 3000 мс, что не соответствует измеренным длительностям старых файлов.

У новых 150 единиц нет legacy-файла: репозиторий формирует числовые номера за пределами прежней библиотеки. Формальная автономность доступа к assets не означает, что звук для каждой карточки существует.

### F05. Исходная проблема состава аудио сохранена

**Где:** `AudioController.kt:106–110`; `scripts/generate_audio.py:124`.

Полный сценарий `playCard` включает только term и meaning. `example_en`, `example_ru`, подробное `explanation_ru` и разбор имени в него не входят. Для смыслового сегмента снова используется `meaning_ru_short`.

Следовательно, эталонное объяснение `zip` с именами/оценками и мнемоника right + split у `rsplit` находятся в данных, но не входят в основной автоматически проигрываемый сценарий. Отдельная кнопка фразы не заменяет требуемый профиль знакомства.

### F06. Повторы старых MP3 снова умножаются

**Где:** `AudioController.kt:136–167`; неизменённые legacy MP3; `generate_full_assets_v3.py`.

Новый контроллер повторяет fallback-файл N раз. Старые файлы сформированы с двумя EN → RU циклами внутри. Поэтому для таких карточек по коду 2x соответствует четырём внутренним циклам, 3x — шести. Фактическое прослушивание в этом аудите не проводилось; вывод следует из сохранённого формата файлов и управления плеером.

`playTerm` и `playExample` при отсутствии сегмента также запускают целый старый переводной трек. Кнопка «слово» перестаёт означать «только слово» и может раскрыть ответ.

### F07. Плеер раскрывает ответ до попытки вспомнить

**Где:** `MainActivity.kt:430–449`, `CardPagerAdapter.kt:105–108`.

При открытии колоды включается autoplay и запускается full `playCard`, содержащий русский смысл. При этом визуально ответ скрыт. Ученик слышит перевод раньше своей попытки и может поставить Good/Easy.

По тапу на тело ещё закрытой карточки также запускается полный сценарий. На паузе смена видимой карточки не обновляет `currentCard` в аудиоконтроллере; Resume способен вернуться к предыдущей. Время оставшихся пауз не хранится, отдельной фоновой медиасессии нет, `onPause()` всегда останавливает поток. Исключение чтения файла вызывает completion, то есть ошибка превращается в обычное завершение.

### F08. Расписание не подключено к занятиям

**Где:** `PracticeDao.kt:13,16`; `MainActivity.kt:289–291, 307–370, 430–479`.

Методы `getDuePractices` и `getNewPractices` объявлены, но не вызываются из учебного потока. Колода открывается целиком и с начала. Повтор Again записывает дату, но не возвращает задание в активную очередь в назначенный срок.

Фактическое сохранение ответа всегда использует `.en_to_ru`; RU → EN только посеяно в таблице. Аудирование, диктант и cloze перечислены в JSON, но экранов и обработчиков этих заданий нет. `FSRS` как отдельный класс ещё не равен работающей системе интервального обучения.

### F09. Миграция не читает реальные старые отметки

**Где:** `RoomMigrationHelper.kt:16–20,41,55–68`; прежний и текущий `ProgressManager.kt`.

Старая версия использует SharedPreferences **`english_flashcards_progress`** и значения **`NEW`, `HARD`, `LEARNED`**. Мигратор читает **`EnglishCardsPrefs`** и распознаёт **`learned`**, **`in_progress`**. В нормальном обновлении прежние отметки не попадают в Room.

Карта `legacy_id_map.json` читается, но не используется; в assets APK её нет. Даже если исправить только имя preferences, ошибочные lowercase-ветки и карта останутся проблемой.

В ветке `learned` дополнительно придуманы stability, три повторения и lastReview. Такие сведения не были сохранены старым приложением. Копировать их сразу в два навыка запрещало исходное ТЗ.

### F10. События ответов ненадёжны, статистика завышена

**Где:** `MainActivity.kt:319–363`; `ReviewEventEntity.kt`.

Запись practice state и review event идёт двумя отдельными DAO-вызовами без общей транзакции. Нет уникального ID попытки и защиты от повторного нажатия/повторной доставки. Длительность каждого ответа жёстко записана **2000 мс**.

После первого Good/Easy выставляется старый LEARNED и увеличивается «выучено». Общая статистика по-прежнему основана на старых preferences, а не на самостоятельных отложенных ответах. Нет отмены оценки, сохранённой сессии и раздельных показателей слушания/вспоминания.

### F11. Ветка Hard нарушает собственные настройки планировщика

**Где:** `FSRSScheduler.kt`, `stepReview`, ветка `Rating.HARD`.

Вычисляется `rawDays=nextInterval(s)`, но для due используется другое выражение на основе прошлого интервала. В независимой пробе исходного Kotlin-кода для Review-карточки с stability 15, difficulty 5, scheduledDays 10 и десятью прошедшими днями:

- retention 0,80 → Hard 12 дней, хотя `nextInterval(updated.stability)` ≈ 66,90;
- retention 0,90 → Hard 12 дней, рассчитанный интервал ≈ 27,90;
- retention 0,97 → Hard 12 дней, рассчитанный интервал ≈ 7,47;
- maximumInterval 10 → Hard всё равно 12 дней.

Четыре штатных теста не сравнивают результаты с зафиксированной эталонной реализацией и этого не ловят. Соответствие заявленной версии FSRS не доказано. Источники для выбора и фиксации эталона: [Open Spaced Repetition, Kotlin](https://github.com/open-spaced-repetition/FSRS-Kotlin), [ts-fsrs](https://github.com/open-spaced-repetition/ts-fsrs). Не следует подменять исправление переходом на новую версию без миграции и сравнительных тестов.

### F12. На экране вместо перевода фразы показывается пояснение

**Где:** `FlashcardRepository.kt:53–56,101`; `CardPagerAdapter.kt:70`.

`primaryRu` прочитан, но не сохранён в `Flashcard`. Вместо него `tvExampleRu` получает `card.exampleNote`, то есть техническое `explanation_ru`. Даже у хорошо подготовленного примера английская строка может оказаться без собственного перевода в интерфейсе.

### F13. «Единый источник» пока является перезаписываемым результатом

**Где:** `scripts/build_content.py`.

Скрипт каждый раз читает старый `backend_words_selection.json`, заново делает `content/cards.json` и выставляет всем `ready`, revision 1. ID зависит от старого номера и текущего написания. Уровень CEFR выбирается по величине старого ID, а часть речи — преимущественно по категории/наличию скобок.

Проба: в копии проекта внесена редакторская фраза в `content/cards.json`, затем вызван документированный `build_content.py --check`. Команда завершилась с кодом 0, изменила файлы и стёрла правку. CLI-параметр не разбирается и read-only проверки не происходит.

### F14. Валидация аудио не является выпускным барьером

**Где:** `scripts/validate_audio.py:30–150`; `scripts/generate_audio.py:146–199`.

Подтверждены три независимых отказа:

1. Один MP3 отсутствует → validator сообщает missing=1, но процесс завершается кодом **0**.
2. Вместо четырёх MP3 записаны невалидные байты с размером >500 → generator сообщает Cache hit, не вызывает синтез и оставляет четыре неверных file hash в результате.
3. Синтез четырёх ролей намеренно завершается исключением → generator печатает Completed и заменяет прежний манифест пустым массивом.

Валидация также перебирает только уже записанные строки манифеста. Отсутствующие строки для большей части учебного корпуса не считаются ошибкой покрытия.

### F15. Значительная часть P1 не подключена к продукту

Нет завершённого пользовательского пути для «Сегодня» с due-очередью, выбора навыка RU → EN, диктанта, cloze, аудиопроверки, микроуроков, словарного поиска, резервного экспорта/импорта и фонового медиасервиса. В Kotlin/XML нет соответствующих обработчиков и экранов; в manifest нет playback service. Рекламировать эти функции только на основании JSON-полей, DAO или файлов в корне репозитория нельзя.

## 5. Повторная оценка исходных 36 сценариев

Статусы: **подтверждён** — условие доказано в указанной области проверки; **частично** — полезная часть реализована, но условие целиком не выполнено; **не выполнен** — обнаружено противоречие или отсутствует обязательная функция; **не проверен** — требуется фактическое устройство/среда.

### A. Содержание

- **A01 — частично.** Текст `rsplit` исправлен, но разбор right + split не включён в автоматическую озвучку знакомства.
- **A02 — частично.** Содержание `zip` улучшено; основная аудиоцепочка не включает подробное объяснение и английскую фразу с переводом.
- **A03 — подтверждён.** В поставленном примере реально используются Animal/Dog и `issubclass`; код выполнен на Python 3.13.5.
- **A04 — частично.** Два `filter` разделены в данных, но предусмотренного поиска нет.
- **A05 — частично.** `getattr` исправлен и реально выполнен на Python 3.13.5; заявленное целевое окружение Python 3.12 отдельно не проверено.
- **A06 — не выполнен.** Исходная запрещённая строка удалена, но сохранены массовые псевдопримеры и новые общие пояснения вместо полной редакторской проверки.
